# Phase 9.9.1 — Multi-retailer reporting and retailer scorecards

## Outcome

One immutable publication represents a named reference retailer and its complete competitive set.
It is not duplicated once per competitor. The application and shareable HTML report default to a
concise all-competitor view and allow the reader to focus every retailer-scoped evidence surface on
one competitor.

The reference retailer is always displayed by catalog name, such as `Walmart (US)`. User-facing
surfaces do not rely on the ambiguous label `Benchmark`.

## Shared deterministic contract

`ReportProjector` emits `retailer_scope` and `retailer_scorecards` in every report view. Each
scorecard selects the overall strict exact-ZIP, exact-package comparison when it exists, then falls
back deterministically to the next available overall comparison. The scorecard contains:

- named reference retailer and competitor identifiers;
- comparison lens;
- matched observations and matched ZIP markets;
- qualifying geographic coverage;
- reference-retailer, competitor, and parity lower-price shares when persisted;
- persisted median prices and competitor-minus-reference median gap when available;
- a plain-language price-position statement; and
- evidence readiness.

No composite retailer rank or invented priority score is calculated. Missing persisted values stay
unavailable; the presentation layer does not infer them from incomplete components.

## Application behavior

The global competitor selector:

- defaults to all competitors;
- persists the selected competitor in the `competitor` URL query parameter;
- remains active while the reader changes report tabs;
- filters comparison tables, segment matrices, product decisions, maps, product highlights, and
  quality examples where retailer identity is present; and
- keeps the named reference retailer visible in two-party evidence.

The Summary tab shows the portfolio retailer scorecard. Selecting a scorecard row focuses the
entire report on that retailer. Portfolio AI prose is deliberately hidden in a retailer-only view
unless a future publication stores retailer-specific narrative, preventing mixed-retailer prose
from being misread as retailer-specific interpretation.

## Artifact parity

Renderer `2.12.0` uses the same scorecard projection for all delivery surfaces:

- HTML includes the global competitor selector, filtered scorecard rows, filtered comparison
  visuals, filtered product decisions, and retailer-aware map points.
- The leadership email includes the five largest evidence-backed retailer scorecards and directs
  readers to the attached report for the remainder.
- XLSX replaces the former coverage-only `Retailer Scorecard` sheet with the shared strict-price
  scorecard. Counts, shares, and currency values retain numeric cell types and user-facing number
  formats.

The HTML attachment in the leadership email is generated by the same renderer as the standalone
HTML artifact.

## Egg acceptance test

Fresh shell eggs remains the multi-retailer stress fixture. A publication with thirteen
competitors must produce thirteen scorecards, retain one canonical publication/checksum, default to
the all-competitor portfolio view, and allow one retailer to be selected without leaking another
retailer's comparison rows or portfolio narrative into that focused view.

## Deferred to Phase 10

Dynamic geography construction belongs to collection-definition administration: all locations,
locations by state, sampled locations per state, demographic rules, and competitor locations
corresponding to an approved reference-retailer geography. Phase 9.9.1 establishes the reporting
contract that will consume that approved geography; it does not add collection-builder mutations.
